# Owner testing notes — 2026-11-10

These notes are preserved for future work. The owner selected **preserve the validated prototype; record notes** for this proposed commit. No new UI architecture or write operations are implemented here.

1. **Export name and case.** Default to the name/case shown for the CP/M file, without a user prefix for single-file export. Reported example: `-CATALOG.310` becoming `user0--catalog.301`. The current code confirms prefix/lowercase behavior; it does not deliberately change `.310` to `.301`. Verify the extension transposition separately rather than treating it as reproduced. Handle cross-user and translation collisions explicitly.
2. **Stored slash versus hyphen.** Display genuine `SIG/M...` names with `/` and suggest `SIG_M...` on export. Do not automatically convert stored hyphens into slashes: volume 310's existing directory actually stores `SIG-M.LZB`. A source-image naming correction is separate from GUI display. Include real slash-name fixtures in acceptance tests.
3. **Configurable filename translation.** Agreed defaults: `/ → _`, `: → ~`, and `\ → ^`. Provide settings to add, edit or remove mappings, using the same configuration on all host OSes and for DOS interchange. Leave pipe, double quote and plus translations unresolved; dollar signs and literal backticks stay unchanged by default. Keep original names separate from host paths, detect collisions, and make reverse translation on import explicit. Original-name metadata or an escaping scheme is still needed for guaranteed reversibility. Colon/backslash compatibility requires backend qualification and new fixtures. See [the agreed policy](FILENAME_POLICY_NOTES.md). Record this requirement without changing the validated runtime in this commit.
4. **Multiple selection.** Select and export multiple files, with destination-directory, duplicate-name, collision, overwrite-refusal, progress and cancellation semantics defined before implementation.
5. **User areas as folders.** A left navigation pane with one folder per user area. Define empty-area visibility and export-directory layout; do not confuse user areas with real CP/M subdirectories.
6. **Changing format closes the image.** Clear the old image/session immediately even if the new layout is wrong. Current code already clears the listing on selector changes; add an explicit acceptance case for invalid-layout transitions before calling this requirement complete.
7. **Host-only filename characters.** See [the full catalogue audit](CATALOG_FILENAME_AUDIT.md). Modern host candidates such as comma/semicolon/equal-sign conflict with CP/M command parsing, but DOS 8.3 forbids these too. There is no universal delimiter-safe escape choice across all profiles merely by picking a character illegal to CP/M. Raw directory bytes, command parsers and CP/M utilities do not all enforce identical rules. Treat mappings as a documented policy, not a claim about all historical CP/M implementations.
8. **Multiple tabs.** Independent image/session/layout/cancellation state per tab; define cross-tab transfers and close-busy behavior.
9. **Image creation.** Future write milestone: explicit validated geometry, empty filesystem initialization, full medium length and erased fill, safe publication and independent validation. The separate SIG/M `buildvol` issues are not changes to cpmimage and do not authorize image mutation here.
10. **Drag-and-drop transfer.** Distinguish host export, future host import, and cross-image transfer. Preserve the read-only guarantee until a separately reviewed write milestone is ready.

The two related filename observations and the translation question are split here for clarity; all original notes are retained. No GitHub issues are created by recording this local backlog.
